kite on Windows
================

From an elevated PowerShell (Run as administrator), in this directory.
Replace CHANGE_ME and tunnel.example.com before running. install refuses
those placeholders.

    $env:RELAY_ADDR = "wss://tunnel.example.com/agent"
    $env:REGISTRATION_KEY = "CHANGE_ME"
    $env:AGENT_NAME = "my-pc"
    $env:SSH_USER = "me"
    .\kite-agent.exe install
    .\kite-agent.exe pair

install sets up the local OpenSSH Server if it is missing
(Add-WindowsCapability OpenSSH.Server~~~~0.0.1.0), sets the sshd service
to Automatic, and starts it. It does not add a firewall rule. kite-agent
dials 127.0.0.1:22 only. If sshd were left on Manual, a reboot would leave
the tunnel up and 127.0.0.1:22 refused. install always sets Automatic.
Re-running install is safe.

pair prints a one-time code such as ABCD-EFGH (10 minutes). It is not the
registration key. The user who ran install can pair without another
elevation prompt while the service is running. On the laptop:

    kite connect --relay wss://tunnel.example.com ABCD-EFGH
    ssh my-pc

The code does not contain the relay address, so the laptop needs --relay
once. kite connect keeps the private key on the laptop (~/.ssh/kite_my-pc,
mode 0600) and sends only the public key. For an administrator, the agent
writes C:\ProgramData\ssh\administrators_authorized_keys and tightens the
ACL to SYSTEM and Administrators. Other accounts use that user's
.ssh\authorized_keys. The comment is "kite-pair <label> <date>".

    kite-agent unpair --list
    kite-agent unpair --revoke laptop

The relay client token is separate. On the VPS: kite-relay tokens revoke <id>.

The service starts at boot, with or without a logged-on user, and it does
not open a console window. It reads %ProgramData%\kite\config.yaml unless
you pass another --config path outside your user profile. The service
command line is only the executable and --config. Do not commit the file.

    kite-agent status     (no elevation required)
    kite-agent list       (no elevation required; kite-agent and kite-agent-*)
    kite-agent pair       (no elevation for the installing user while running)
    kite-agent stop       (elevated)
    kite-agent start      (elevated)
    kite-agent restart    (elevated)
    kite-agent uninstall  (elevated; leaves the config file in place)

Logs: %ProgramData%\kite\kite-agent.log

A second service:

    .\kite-agent.exe install --service-name kite-agent-test

Use a different AGENT_NAME. Its files are under
%ProgramFiles%\kite\kite-agent-test\ and
%ProgramData%\kite\kite-agent-test\.

To replace a running exe even if this SSH session dies when the tunnel
restarts:

    .\kite-agent.exe upgrade --from C:\path\to\new\kite-agent.exe

That schedules a one-shot SYSTEM task and returns. The result is
%ProgramData%\kite\upgrade.log.

install-kite-agent.ps1 in this zip calls the same install command.

Linux uses the systemd unit in the source repository (deploy/kite-agent.service).
macOS uses deploy/com.kite.agent.plist, or sudo kite-agent install for a
system LaunchDaemon. Neither file is in this zip.

中文
====

在本目录用提升权限的 PowerShell（以管理员身份运行）。运行前换掉 CHANGE_ME
和 tunnel.example.com。install 会拒绝这两个占位符。

    $env:RELAY_ADDR = "wss://tunnel.example.com/agent"
    $env:REGISTRATION_KEY = "CHANGE_ME"
    $env:AGENT_NAME = "my-pc"
    $env:SSH_USER = "me"
    .\kite-agent.exe install
    .\kite-agent.exe pair

install 会在缺少 OpenSSH Server 时安装它
（Add-WindowsCapability OpenSSH.Server~~~~0.0.1.0），把 sshd 设为自动启动
并启动。它不会添加防火墙规则。kite-agent 只拨 127.0.0.1:22。如果 sshd 停在
手动启动，重启后隧道还在，但 127.0.0.1:22 会被拒绝。install 总会把它设成
Automatic。再跑一次 install 是安全的。

pair 打印一次性配对码，例如 ABCD-EFGH（10 分钟）。它不是注册密钥。执行
install 的用户在服务运行时不需要再提权。在笔记本上：

    kite connect --relay wss://tunnel.example.com ABCD-EFGH
    ssh my-pc

配对码里没有中继地址，所以笔记本第一次要带 --relay。kite connect 把私钥留在
笔记本上（~/.ssh/kite_my-pc，权限 0600），只发送公钥。管理员账户会写到
C:\ProgramData\ssh\administrators_authorized_keys，并把 ACL 收成只有 SYSTEM
和管理员。其它账户使用该用户的 .ssh\authorized_keys。注释是
「kite-pair <标签> <日期>」。

    kite-agent unpair --list
    kite-agent unpair --revoke laptop

中继上的客户端令牌是另一回事。在 VPS 上执行 kite-relay tokens revoke <id>。

服务开机就会启动，不需要有人登录，也不会弹出控制台。它读取
%ProgramData%\kite\config.yaml，除非你用 --config 指向用户目录以外的路径。
服务命令行只有程序和 --config。不要把这个文件提交到 git。

    kite-agent status     （不需要提升权限）
    kite-agent list       （不需要提升权限；列出 kite-agent 和 kite-agent-*）
    kite-agent pair       （服务在跑时，安装者不用再提权）
    kite-agent stop       （需要提升权限）
    kite-agent start      （需要提升权限）
    kite-agent restart    （需要提升权限）
    kite-agent uninstall  （需要提升权限；配置文件会留下来）

日志：%ProgramData%\kite\kite-agent.log

再装一个服务：

    .\kite-agent.exe install --service-name kite-agent-test

请使用不同的 AGENT_NAME。文件在 %ProgramFiles%\kite\kite-agent-test\ 和
%ProgramData%\kite\kite-agent-test\。

即使这条 SSH 会话会在隧道重启时断开，也可以替换正在运行的程序：

    .\kite-agent.exe upgrade --from C:\path\to\new\kite-agent.exe

upgrade 注册一个以 SYSTEM 运行的一次性任务后就返回。结果写在
%ProgramData%\kite\upgrade.log。

本压缩包里的 install-kite-agent.ps1 调用同一条 install 命令。

Linux 的 systemd 单元和 macOS 的 plist 在源码仓库的 deploy\ 目录里。macOS
也可以用 sudo kite-agent install 安装系统 LaunchDaemon。这些文件不在这个
压缩包中。
